# PDF Studio

An open-source, cross-platform PDF reader and editor: view, annotate, organize, fill forms, sign, edit and redact.

## Decisions

- **Platforms:** macOS, Windows, Linux (desktop app), and any modern browser as an installable web app (PWA)
- **License:** open source under **MIT**. Every dependency must use a permissive license (MIT, Apache-2.0, BSD). No GPL/AGPL code, so MuPDF is deliberately not used
- **Shell:** Tauri (Rust backend, web UI, MIT/Apache-2.0) for small installers and native file access
- **UI:** TypeScript + React
- **Rendering:** PDF.js (Apache-2.0) for pages, text layer, search and outline
- **Page operations, forms, stamping:** pdf-lib (MIT)
- **Text editing, image editing and true redaction:** PDFium (BSD-3-Clause / Apache-2.0) compiled to WebAssembly, via @embedpdf/pdfium (MIT); loaded only when editing
- **Digital signatures:** node-forge, used under its BSD-3-Clause licence (it's dual-licensed BSD-3-Clause or GPL-2.0; we choose BSD), for digital IDs and RSA signing; the CMS signature structure (PAdES baseline) and the incremental PDF update are written in this project
- **OCR:** Tesseract.js (Apache-2.0) with tessdata language models (Apache-2.0, via MIT-licensed packages); the invisible-text font is generated by scripts/make-glyphless-font.py
- **Word export:** fflate (MIT) for the .docx container; the document itself is built in this project
- **Password protection:** AES-256 via PDFium's encryption functions

## Roadmap

1. **Viewer:** open files, tabs, zoom, thumbnails, search, outline/bookmarks, dark mode
2. **Annotate:** highlight, underline, comments, freehand, shapes, stamps
3. **Organize:** merge, split, reorder, rotate, delete pages, compress
4. **Forms:** fill AcroForms, create form fields
5. **Sign:** draw/type/image signatures, then certificate-based digital signatures and verification
6. **Edit:** edit text and images, true redaction
7. **Extras:** password protection, OCR, convert to/from images, export to Word (AI summarize / ask-the-PDF deliberately left out for now)

## Known hard problems

- **Editing existing text:** PDFs store positioned glyphs, not paragraphs, and fonts are often subset. The approach is to remove the original text and lay out new text in a matching font, falling back to a similar font when glyphs are missing.
- **Trusted signatures:** Signatures appear "trusted" in other readers only when the certificate chains to a CA on their trust list.
- **XFA forms:** Legacy dynamic forms are out of scope for now.

## Status

**Stage 1 (viewer) is done:**

- Tabs for several open documents; open via the file picker, drag and drop, or the OS ("Open With", double-click once installed as the PDF handler)
- Continuous scrolling, with only the pages near the screen drawn so large files stay fast
- Zoom: fit width, fit page, presets, +/-, pinch or Ctrl/⌘ + scroll
- Rotate view, go to page, page thumbnails, outline (bookmarks)
- Selectable, copyable text
- Find with highlighted results, match case, next/previous
- Internal links and external links (opened in the browser)
- Password-protected PDFs
- Light, dark and system theme, plus night reading (dark pages)

**Stage 2 (annotate) is done:**

- Highlight, underline and strikethrough by selecting text
- Sticky notes, freehand drawing, rectangles, ellipses, lines, arrows, text boxes and stamps (Approved, Draft, Confidential…)
- Select, move, resize and delete; change colour, line width and font size
- Comments on any annotation, with a Notes panel listing them all
- Undo and redo
- Save and Save As. Annotations are written as standard PDF annotations, so other readers (Preview, Acrobat, Chrome…) show them
- Annotations made here stay editable when the file is reopened in PDF Studio
- Warns before closing a tab or quitting with unsaved changes

**Stage 3 (organize) is done:**

- Organize view: a page grid with drag to reorder (several pages at once), rotate, delete, duplicate
- Insert pages from other PDFs or blank pages, anywhere
- Extract selected pages into a new document
- Split into several files (every N pages, or at selected pages)
- Combine several PDFs into one
- Reduce file size: re-saves photos at a lower resolution (three levels) and drops unused data; shows the result before you keep it
- Page changes and annotation changes share one undo history; annotations move with their pages

**Stage 4 (forms) is done:**

- Fill in any PDF form: text (single and multi-line, character limits, combed boxes), checkboxes, radio buttons, dropdowns and lists; read-only fields are respected
- "Highlight fields" and "Clear form"; required fields are marked when empty
- Each change is one undo step, shared with annotations and page edits
- Saved values get proper appearances, so they show the same in Preview, Acrobat and browsers
- Add new fields (Forms button): text, checkbox, radio groups and dropdowns; move, resize, rename, set choices, font size, multi-line and required
- Fields added in PDF Studio stay editable when the file is reopened, and follow their pages in Organize

**Stage 5 (sign) is done:**

- Handwritten signatures and initials: draw (mouse, trackpad, pen or finger), type (in a handwriting font already on your system), or upload a photo of your signature; the paper background is removed
- Saved signatures for reuse (kept on this device only); place, move and resize them; add today's date
- "Sign here" fields in forms: click to sign
- Digital signatures with a digital ID: import a .p12/.pfx (including older Keychain/Windows exports) or create a self-signed ID; IDs stay password-protected on this device and the password is never stored; export a backup
- Visible (with your handwritten signature, name, date, reason and location) or invisible digital signatures; sign into an existing signature field
- Signing appends to the file (incremental update), so earlier signatures stay valid and documents can be countersigned
- Signatures follow PAdES baseline (ETSI.CAdES.detached, SHA-256, signing-certificate-v2) and verify with OpenSSL
- Opening a signed PDF checks every signature and shows whether it's valid, whether the document changed after signing, and who signed; signed files are protected from edits that would break them

Limits for now: only RSA digital IDs can sign and be checked (most personal IDs are RSA); there's no trusted-authority (CA) check or timestamp server yet, so identities show as "not verified by a trusted authority"; signing saves a new signed copy.

**Stage 6 (edit and redact) is done:**

- Edit text in place: click a line, change it; the original font is kept when it has every character you type, otherwise the closest standard font (Helvetica, Times, Courier) is used. Position, size and colour are kept, and so is reading order
- Pictures: move, resize (keeps its shape) and delete; add new pictures
- True redaction: mark areas (drag) or text (select it), then apply. Text is removed character by character (partly covered lines are rebuilt from what's left), covered parts of pictures are blacked out in the image data itself, drawings and comments in the area are removed, form fields there are deleted with their values, PDF Studio's own annotations there go too, and the old page content is dropped from the file. Optionally removes document info (title, author…)
- Every edit is one undo step, shared with everything else

Limits for now: changed text doesn't reflow the rest of the line or paragraph; rotated text can't be edited; drawings only partly under a redaction mark are covered but not cut; the editing engine downloads (2 MB) the first time Edit is used in the web app, and works offline after that.

**Stage 7 (extras) is done:**

- Password protection: require a password to open, and/or restrict printing, copying, changes and comments behind a permissions password (AES-256). Remove protection. Encrypted PDFs now open fully editable after their password, are protected again with the same passwords when saved, and documents whose author restricted changes stay locked until the permissions password is given
- OCR: "Make it searchable" for scanned documents (offered automatically), in 17 languages. Adds an invisible, exactly positioned text layer so you can search, select and copy; works in other readers too (tested with Apple's PDFKit). English is built in; other languages download once
- Export pages as PNG or JPEG (72–600 dpi, any pages), including annotations, signatures and form values
- New PDF from pictures (also by dropping pictures on the window): A4, Letter or each picture's own size
- Export to Word (.docx): text regrouped into paragraphs, headings, bold/italic, fonts, sizes, centred lines and pictures

Not included: AI summaries and questions (they'd send document text off the device). Word export is approximate for columns, tables and complex layouts; scanned pages need OCR before exporting to Word.

**Web app (PWA) is done:**

- Installable from Chrome, Edge and Safari ("Install app" button, or Add to Home Screen); runs in its own window
- Works fully offline once loaded: the app, PDF engine, fonts and character maps are cached
- Files never leave the device: there is no server, everything runs in the browser
- In Chrome and Edge, Open and Save work on real files (Save writes back to the same file), dropped files keep that link, Split writes into a chosen folder, and the installed app can be the system's "Open with" choice for PDFs. Other browsers download a copy instead
- Shows an "Update now" bar when a new version is ready (never reloads over unsaved work)
- Two-finger pinch zoom on phones and tablets; zooming keeps the spot under your fingers or cursor in place

Limits for now: form text is drawn with Helvetica, so values in non-Latin scripts are left for the reader app to draw (the value itself is saved). Fields that already existed in a file can be filled but not moved or renamed. JavaScript in forms (calculations, validation) isn't run. Text boxes and stamps use Helvetica, so characters outside Western European languages appear as "?" in the saved file (the text itself is kept). Encrypted PDFs can be read and annotated but not saved or reorganized. Compression only shrinks JPEG photos (most scans and camera images); other image types are left as they are. Annotations made in other apps are shown but can't be edited yet.

## Development

Requires Node 20+ and Rust (for the desktop build).

```bash
npm install
npm run dev          # web app in development, at http://localhost:1420 (no offline caching)
npm run build        # production web app in dist/
npm run preview      # serve dist/ at http://localhost:4173 to test install and offline
npm run tauri dev    # desktop app
npm run tauri build  # installers
npm run sample       # regenerate public/samples/sample.pdf
```

### Hosting the web app

`dist/` is a static site: upload it to any static host with HTTPS (GitHub Pages, Netlify, Vercel, Cloudflare Pages…). Service workers need HTTPS (localhost is exempt). Two settings matter:

- **Sub-path:** if the app lives at e.g. `https://example.com/pdf-studio/`, build with `VITE_BASE=/pdf-studio/ npm run build`.
- **Single-page app:** unknown paths should serve `index.html` (most hosts do this for SPAs; the service worker also handles it once installed).

The desktop build never registers a service worker; the PWA plugin switches itself off when Tauri builds.

In the web UI during development, `http://localhost:1420/?file=/samples/sample.pdf` opens the sample straight away.

### Project layout

- `src/lib/` — PDF loading (`pdf.ts`), search, desktop/browser bridge (`platform.ts`), view state
- `src/lib/annotations.ts` — the annotation model (PDF coordinates) and undo history
- `src/lib/forms.ts` — form model (values by field name, placed fields) and reading PDF.js widgets
- `src/lib/pdfForms.ts` — writes values and placed fields into the PDF with pdf-lib, and reads placed fields back out
- `src/lib/signatures.ts` — saved handwritten signatures; `digitalId.ts` — importing and creating digital IDs
- `src/lib/cms.ts` — building and reading CMS signatures; `pdfSign.ts` — signing by incremental update; `pdfVerify.ts` — checking signatures
- `src/lib/pdfSecurity.ts` — password protection; `ocr.ts` — text recognition; `images.ts` — pages to pictures and back; `docx.ts` — Word export
- `src/lib/pdfium.ts` — loading the PDFium engine; `pdfEdit.ts` — redaction, editing text and images
- `src/lib/pdfPages.ts` — page operations (reorder, rotate, delete, insert, merge, extract) and compression
- `src/lib/pdfWrite.ts` — writes annotations into the PDF with pdf-lib, and reads PDF Studio's own back out on open
- `src/components/` — `Viewer` (scrolling and layout), `PageView` (one page: drawing, text, links, highlights), `AnnotationLayer` (drawing and editing annotations on a page), `AnnotateBar`, `CommentsPanel`, `OrganizeView`, `CompressDialog`, `FormLayer` (inputs over the page, placing fields), `FormsBar`, `SignMenu`, `SignatureDialog`, `DigitalSignDialog`, `SignatureBanner`, `EditLayer`, `EditBar`, `ProtectDialog`, `OcrDialog`, `ExportDialog`, `ImagesToPdfDialog`, `Sidebar`, `Toolbar`, `SearchBar`
- `src/pwa.ts` — service worker registration, install prompt and update notice (web only)
- `src/lib/platform.ts` — desktop vs browser: file dialogs, File System Access (save in place), drag and drop, "Open with"
- `src-tauri/` — the desktop shell: reading and safely writing files, native menu, "Open With" handling

### How saved annotations stay editable

Each annotation PDF Studio writes is a normal PDF annotation with its own appearance, plus a private `/PDFStudio` entry holding the original data as JSON. On open, those annotations are taken out of the file and turned back into editable objects; saving writes them in again. Other apps ignore the private entry.
